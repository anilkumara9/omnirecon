OmniRecon

Reverse engineering & reconnaissance MCP server for AI coding agents. Point it at a web app, API, APK, or codebase — get back an evidence-backed rebuild blueprint.

GitHub Repo Quickstart

What it does

🌐 Web platforms

Autonomous browser crawls routes, clicks workflows, captures live XHR/WebSocket traffic, extracts design tokens from rendered styles.

🔌 REST APIs

Endpoint discovery from JS bundles, live probing, values-free schema inference, OpenAPI 3.1 export with evidence tags.

📱 Android APKs

Manifest parsing, DEX class/method inventory, interesting-API detection (network, crypto, reflection).

🖥️ Electron apps

.asar introspection, IPC channel inventory, BrowserWindow security prefs.

📦 Codebases

AST route extraction, component inventory, state management, auth files, migrations.

✅ Evidence ledger

Every finding classified: OBSERVED / SOURCE_VERIFIED / INFERRED / UNVERIFIED / BLOCKED. Nothing invented, ever.

Quickstart

git clone https://github.com/anilkumara9/omnirecon.git
cd omnirecon
./install.sh   # Linux/macOS — or install.bat on Windows

# connect your agent (zero path mistakes):
.venv/bin/python -m omnirecon.cli setup claude-code

# or use the CLI directly:
.venv/bin/python -m omnirecon.cli recon-start https://example.com --mode fast

Works with Claude Code, Codex CLI, Cursor, Windsurf, Zed, and any MCP-compatible client. Full guide in the README.

FAQ

What can I reverse engineer?

Web apps, REST APIs, Android APKs, Electron apps, and codebases — anything with an observable surface. Server internals and authed areas you can't access are recorded as BLOCKED/UNVERIFIED, never invented.

How is it different from REA?

REA is the authority on deep binary decompilation and deliberately passive on the web. OmniRecon drives a real browser autonomously and bridges to REA for binaries.

Does it work without an MCP client?

Yes — all 21 tools are mirrored in the CLI.
